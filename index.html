Six building blocks for any process

Each block is a few lines in .natamux.json, or a few clicks in Project settings → Stages. Put them in any order your team works in.

Stages and gates

A stage is one step of the work, such as Spec, Implement or Review. Natamux starts it, checks the result and goes on. A stage with Wait for my approval stops until you click Approve, so nothing gets built from a spec you did not read.

More in the docs: Gates

.natamux.json

{ "id": "spec", "gate": "manual" }

Side by side

A group holds 2 to 4 stages that work at the same time, each in its own shell. Here Test spec writes the cases from the spec alone while Implement builds. The group is done when every stage in it is done.

More in the docs: Stages that run side by side

.natamux.json

{ "id": "build", "parallel": [
  { "id": "test-spec", "agent": "gemini" },
  { "id": "implement" }
] }

Branches

A branch splits the pipeline into 2 to 4 paths. When a task gets there, Natamux checks the conditions in order, and the task takes the first path that holds. A condition is File has text or Command succeeds (the command exits with 0). The last path can be the Otherwise path. The Progress tab then says Took Bug fix and folds the other paths into Not taken.

More in the docs: Paths with a condition

.natamux.json

{ "id": "triage", "name": "Bug or feature",
  "paths": [
    { "id": "bugfix", "name": "Bug fix",
      "when": { "type": "command",
        "run": "grep -qi bug .natamux-task/context.md" },
      "stages": [{ "id": "reproduce" }] },
    { "id": "feature", "name": "Feature",
      "stages": [{ "id": "plan" }] }
  ] }

Send back

A review agent that finds a problem runs natamux stage back with the reason. The task goes back to Implement, and its agent gets the reason in its next prompt. Set a limit on how often an agent sends back from one stage, and past it the task waits for you. A person can send back from any stage, any time.

More in the docs: The review loop

The review agent runs

natamux stage back $NATAMUX_TASK_ID --to implement \
  --reason "A coupon larger than the total makes it negative"

CI as a stage

Tick Tasks can check it on CI on a stage, and each task gets a Check on CI box. When the stage is done, Natamux pushes a snapshot of the worktree to natamux-ci/<branch> and waits for your CI. A red run goes back to the agent with the end of the failed log. After two such send backs, the next failure waits for you.

More in the docs: Check a stage on CI

.natamux.json

{ "id": "implement", "ci": true }

An agent per stage

A stage can start its own agent, with its own arguments such as a model. It runs in a shell of its own, so a reviewer reads the diff with fresh eyes. Set Agent and Arguments in the stage settings. They are saved in .natamux.json, so the whole team uses them.

.natamux.json

{ "id": "agent-review", "name": "Review",
  "agent": "codex", "args": "--model gpt-5" }

Bring the agents you already use

Natamux starts five agents for you and adds hooks to each session, so the dashboard knows within a second who works, who asks and who is done. Each worktree is trusted for the agent it starts.

  • Claude CodeclaudeHooks through its settings file. The only agent that runs a stage as a workflow.
  • CodexcodexHooks passed on the command line for that run.
  • Gemini CLIgeminiHooks in a system settings file Natamux points it to.
  • GitHub CopilotcopilotHooks in the worktree, kept out of git.
  • Cursorcursor-agentHooks in the worktree, kept out of git.
  • Any other CLIyour-agentRuns in a plain shell. The terminal bell and natamux ask or done report back.

Fits the project you already have

  • A worktree and a branch for each task, so agents never touch each other's files or your checkout
  • .natamux-setup prepares each new worktree: install, seed, copy env
  • Ten ports for each task, the first in $PORT, so dev servers do not clash
  • Checks and conditions are any shell command, so any language and build tool works
  • macOS, Windows and Linux. On Windows the script is .natamux-setup.ps1
  • Export a workflow from one project and Import... it into another. Import lists every command first

See every task, and the one that needs you

The sidebar sizes each task by how much it needs you. A running task shows its stage, and finished work folds to one line. Open a task and its stages stay in sight beside the terminal.

Git and GitHub without leaving the task

Every task works in its own worktree on its own branch.

  • Generate asks the task's agent for a commit message from the diff. Then Commit all.
  • Side-by-side diffs, image diffs, and a comment on any line that goes straight to the agent
  • Push, then Create PR with the GitHub CLI. The body ends with Closes #N
  • Natamux watches the PR checks; a merged PR finishes the task
  • Import issues turns open GitHub issues into tasks

More in the docs: GitHub

One command for you and your agents

natamux, or nmx for short. Agents use the same command to ask you something, say a stage is done, or send the work back.

# You, in any shell
$ nmx task create "Export the report as CSV" --label reports
$ nmx agent start T-0010 --agent codex

# The agent, in its task terminal
$ natamux ask "Keep the old CSV columns, or drop them?"
$ natamux done

# The review agent, when something must change
$ natamux stage back $NATAMUX_TASK_ID \
    --reason "Empty rows break the export"

More in the docs: CLI reference

Your code stays on your machine

  • No account, no telemetry. Besides the update check, it talks to GitHub only through your own git and gh, for example to follow your pull requests and CI.
  • Local daemon. It listens on 127.0.0.1 and wants a token on every request.
  • Open source. GPL-3.0 licensed. Your agents and the GitHub CLI use their own sign-in.

curl -fsSL https://natamux.github.io/install.sh | sh

macOS blocks the first start

The app is not signed with an Apple certificate yet. The one-line command handles this for you. After a manual download, open System Settings → Privacy & Security and click Open Anyway. Or run:

xattr -dr com.apple.quarantine /Applications/Natamux.app
