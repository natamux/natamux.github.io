Terminal and Agents view

Every task with a workspace has a Terminal tab. It holds real terminals that run in the task’s worktree folder. The task’s agent runs in Terminal 1 for the whole task; stages that run beside it start their own agents in Terminal 2 and Terminal 5. A stage with its own agent or arguments runs it in a terminal of its own, from Terminal 6. See Choose a model. The Agents view puts the agents of many tasks in one grid.

Open the terminal

Section titled “Open the terminal”
  1. Select a task that has a workspace.
  2. Double-click it, or press Enter. The workspace opens on the terminal while an agent works.
  3. From another tab of the workspace, click Terminal or press 1.

When you switch to another task’s workspace, the keyboard goes to its first agent terminal, so you can type to the agent at once. A terminal you pick with Jump to a workspace gets the keyboard instead.

A task without a workspace shows Start agent and a way to make a workspace instead. See Workspaces.

Terminals

Section titled “Terminals”

The tab shows each terminal in its own pane. Terminal 1 is always there. The agent runs in Terminal 1. Its pane header shows the agent’s icon and name, such as Claude Code (only the icon in a narrow pane), and the state of its stage, for example Running · Edit a.ts. When stages run side by side, each terminal shows the state of its own stage. In Agents, the grid shows Terminal 1 and names another terminal that needs you.

To do this Do this
Add a terminal Click New terminal, or press Ctrl+Shift+`
Maximize a pane Click Maximize Terminal N, or press Mod+Shift+Enter in the pane
Restore a pane Click Restore Terminal N, or press Mod+Shift+Enter again
Close a terminal Click Close terminal (ends the process) in the pane header
Find text Press Mod+F. On Windows and Linux, press Ctrl+Shift+F in a terminal

Mod is ⌘ on macOS and Ctrl elsewhere. Ctrl+Shift+` is Ctrl on every platform.

Things to know:

  • A task has at most 6 terminals. New terminal is off after that.
  • Terminal 1 has no close button. It stays for the agent.
  • You can start an agent yourself in any terminal, for example type codex or agent (Cursor) in Terminal 2. Its pane header then shows that agent, even when the task has another one. A terminal that runs another program, such as vim, shows no agent. On Windows, a header shows only an agent that Natamux started.
  • An agent you start yourself in an extra terminal has a state of its own, such as Running or Needs input, when its hooks reach Natamux. It does not change the task’s state or stage. Cursor and Copilot read their hooks from the worktree, which Natamux prepares for every terminal. Claude Code, Codex and Gemini started by hand show their name but no state.
  • New terminals are named in order: Terminal 2, Terminal 3, and so on.
  • Panes sit side by side and fill the width. The last pane takes the rest of its row.
  • On a phone, one terminal fills the screen. Chips named Terminal 1, Terminal 2 switch between them.
  • Closing a terminal ends its process and everything that runs in it.
  • A terminal keeps running when you close the dashboard. Open it later and the pane shows the last screen again, drawn for the pane’s size.
  • When the connection to a terminal drops, for example after your computer sleeps or the network changes, the pane shows Reconnecting. and connects again by itself. The screen stays as it was, and the output you missed follows.
  • When a task is done or cancelled, Natamux keeps the last screen of each terminal, then ends the terminals with the agent. A terminal where another program runs, such as a dev server, keeps running until the program stops. The Terminal tab then shows the wrap-up: click Show last screen to read what a terminal printed last. Click Open a new terminal to open a plain terminal in the workspace; it does not start the agent, and Back to wrap-up returns. To ask the agent something more, click Reopen agent: the agent starts again in Terminal 1 and goes on with its last conversation, with no new prompt. The task stays done or cancelled. When no pane shows that terminal for a minute, it ends too, unless a program runs in it.
  • An ended terminal keeps its screen, dimmed, with no cursor, and takes no keys. You can still scroll, select, copy and find in it. A bar at the bottom says The terminal ended. and offers Open a new terminal.
  • When the same terminal is open in two places, for example in Agents and in its workspace, the pane you type in or click in sets the terminal’s size. Programs such as agents draw for that size.
  • Natamux runs at most 64 terminals in all.

To jump to an extra terminal of any workspace, press Mod+J outside a terminal, or use Search or run a command. The palette lists the extra terminals under their workspace.

Find in the terminal

Section titled “Find in the terminal”

Mod+F (Ctrl+Shift+F on Windows and Linux) opens Find. Press Enter for the next match and Shift+Enter for the previous one. Match case and Use regular expression are toggles. Esc closes the bar.

When you scroll up, Jump to latest brings you back to the end. Links to web addresses open in a new tab. A terminal keeps its screen and the history above it while no one looks at it, so when you switch tasks or reload the dashboard, you can scroll back as far as the pane could. In the desktop app, a terminal that fell far behind its output (an agent that prints a lot while the pane is hidden, or a lost connection) comes back with only its last 1,000 lines of history, so it shows again sooner. When the pane is narrower or wider than before, long lines wrap again to fit it, as in any terminal.

Like Ghostty, the history is limited by memory, about 10 MB for each terminal, not by a number of lines. So a narrow pane keeps more lines than a wide one:

Pane width Lines kept above the screen
80 columns about 7,800
120 columns about 5,200
200 columns about 3,100

A pane keeps at most 10,000 lines and at least 1,000. When a pane gets wider, its oldest lines go first. The output is gone when the terminal ends, or when Natamux restarts or updates.

Font and drawing

Section titled “Font and drawing”

Terminals draw with the GPU (WebGL), as native terminals do, and fall back to the browser’s own drawing when WebGL is off. When you switch tasks, the terminals fade in at their final size, so the programs in them do not redraw. When a pane changes size, for example after New terminal or closing a terminal, the pane keeps its frame, and the screen fades in once the program has drawn for the new size. A change of the task state never changes the size of the panes, so the terminals stay as they are. Programs that draw a whole screen at once, such as Claude Code, do not flicker: Natamux waits for the end of each screen update (synchronized output). Emoji and other wide signs take two columns.

To change the font, open the Account menu at the bottom right and click Terminal font…. Type a font family that is installed on your machine and a size in pixels. Leave a field empty to use the default.

In the desktop app, the default is your Ghostty font: Natamux reads font-family and font-size from Ghostty’s config file each time the dashboard loads. Without a Ghostty config, the default is JetBrains Mono at 13px.

Natamux bundles the Nerd Font icons, as Ghostty does. Prompt themes such as Starship or Powerlevel10k and eza --icons show their icons with any font, without installing a Nerd Font.

When several panes show, the pane that has the focus has an outline. Click a pane to type in it.

Keys that belong to the shell

Section titled “Keys that belong to the shell”

Inside a terminal, the shell gets your keys. On macOS the ⌘ shortcuts of Natamux still work. On Windows and Linux only the function keys and Ctrl+Shift shortcuts reach Natamux. Ctrl+K, Ctrl+B and Ctrl+J stay with the shell. See Keyboard shortcuts.

The agent in Terminal 1

Section titled “The agent in Terminal 1”

Start agent types the agent’s command into Terminal 1. You see it start like any program. See Agents and hooks.

Type to the agent

Section titled “Type to the agent”

Click in the pane and type. Your keys go straight to the agent. This is how you answer a question.

When an agent asks something, the task goes to Needs input and the current stage card in the Progress view of the details shows what it asks (on a phone, a banner under the header). With the details closed, click Needs input in the workspace header to open them. When the workspace shows more than one agent pane, the waiting pane says Needs input in its header. Click Answer in terminal to put the cursor in Terminal 1. If you answered another way, click Resume. When the agent ended its turn and still runs, Resume asks it to go on with the stage.

After you quit and open the app again, Natamux starts the agent of each running, waiting or in-review task again, in its terminal. Claude Code goes on with the same conversation; other agents start again with the stage prompt. The task keeps its state. The other terminals of the task come back too, see A terminal after a daemon restart.

Send a message to the agent

Section titled “Send a message to the agent”

You can send text to the agent without typing in the terminal. In the Changes tab, write a comment under the diff and click Send now. Natamux pastes it into Terminal 1 as the agent’s next prompt and presses Enter. See Changes and history.

This works only while an agent runs in Terminal 1, or is paused there. Otherwise Natamux answers No agent runs in the terminal of T-0001. Start the agent first. That check keeps a comment from running as shell commands.

Needs input or failed

Section titled “Needs input or failed”

A failed task shows the reason in its current stage card in the details (on a phone, in a banner under the header). Use Start agent or Restart agent to run the agent again. For the task states, see Tasks.

An idle agent pauses

Section titled “An idle agent pauses”

An agent that ended its turn still uses memory while it waits. When it has waited 30 minutes and no window shows its terminal, Natamux pauses it: it ends the terminal and keeps the agent’s conversation.

  • The pane keeps the last screen, dimmed, with Paused after 30 min idle. Starts again when shown.
  • Open the task, show the pane, or type in it, and the agent starts again on the same conversation. The keys you typed go to it once it runs.
  • A new stage in that terminal, or a comment from Send now or Send N comments, starts the agent on its conversation with that prompt.
  • An agent that asks something, works, or waits for its background work does not pause. Nor does an agent that never named its conversation.
  • After a daemon restart, a paused agent stays paused until you show it.
  • The task’s activity log says Agent paused after 30 min idle.

To change the minutes, or to turn the pause off with 0, use Pause idle agents after (min) on the Stages tab of the project settings, or agents.pauseIdleAfterMinutes in .natamux.json.

The Agents view

Section titled “The Agents view”

Click Agents in the sidebar to watch the agents of many tasks at once. Each pane is Terminal 1 of a task, live, and you can type in it as in the workspace.

  • Until you pick panes yourself, the grid shows the tasks that are running or need your input, in the order of their ids.
  • Add a pane adds a task. The grid holds up to 6 panes. Shift+Enter in the command palette also adds the selected task.
  • Columns sets the layout: 1, 2, 4 or Auto. Auto balances the rows, so five panes in four columns become 3 + 2.
  • The pane header shows the task id and title, the agent, and the state of its stage. Click the title, or the Open workspace button, to open the task.
  • When another terminal of the task needs you, for example the Test spec agent in Terminal 2, the pane says so.
  • Maximize a pane with its button or Mod+Shift+Enter.
  • The close button removes the pane from Agents. The agent keeps running.
  • With no pane, the view says No agent is working and offers Add a pane.

Natamux keeps your choice of Columns in this browser. Panes keep their order when tasks change state.

A terminal after a daemon restart

Section titled “A terminal after a daemon restart”

Terminals belong to the daemon. When the daemon stops, it ends every terminal, and an agent in a terminal ends with it.

Natamux remembers the terminals of each task that is not done or cancelled. After a restart:

  • The agent of a running, waiting or in-review stage starts again at once, as in Type to the agent.
  • Every other terminal comes back with the same name when you open its task, or when the Agents view shows its Terminal 1. Until then nothing runs in it, so the start stays fast.
  • An agent comes back on its last conversation, with no new prompt. It waits for you, and the task keeps its state.
  • A plain terminal, and a terminal whose agent never named its conversation, come back as a plain terminal in the workspace folder.
  • A terminal you closed, or that a stage closed with endShell, does not come back. A terminal whose agent you quit comes back as a plain terminal.

While a terminal comes back, its pane shows a spinner and Restoring GitHub Copilot… (the name of its agent), or Restoring terminal…. The spinner goes once the agent runs, after 15 seconds at most.

The old screen of a plain terminal and the programs in it, such as a dev server, are gone. Your files and your git state are not.

When a pane changes size, for example when a panel opens or a new terminal is added, Natamux hides it while the size changes and fades it in after the terminal has redrawn.

While the daemon is down, the pane shows Reconnecting. If a pane shows The terminal ended. and an Open a new terminal link at the bottom, click it. If it shows The terminal could not start. at the top, click Start a new terminal instead. Natamux opens a fresh terminal in the same workspace folder.

For a task whose agent does not start again on its own, use Start agent.

Ports

Section titled “Ports”

Each task has its own block of 10 ports so dev servers of different tasks do not clash. The block starts at 20000 + 10 × the number at the end of the task id, and the number wraps after 1000 tasks. T-0001 gets 20010 to 20019, and so does ABC-1. The details panel shows the range as Dev ports, with a note that the first port is $PORT.

Environment variables

Section titled “Environment variables”

Every terminal starts with your daemon’s environment plus these variables.

Variable Value
NATAMUX_TASK_ID The task id, such as T-0001
NATAMUX_TERMINAL The terminal name, such as 1
NATAMUX_URL The daemon address on loopback, such as http://127.0.0.1:4317
NATAMUX_TOKEN The daemon token
PORT The first port of the task’s block
NATAMUX_PORT The same value as PORT
TERM xterm-256color

Caution

In a terminal, NATAMUX_PORT is the task’s first dev port, not the daemon’s port. Use NATAMUX_URL to reach the daemon.

NATAMUX_URL and NATAMUX_TOKEN let the natamux command and agent hooks work in the terminal without setup. The terminal starts in your login shell ($SHELL, else /bin/bash, else /bin/sh). On Windows it is PowerShell.

Because the terminal gets the token, treat what you run in it as trusted. See Security and privacy.
