Desktop app

The Rust desktop app starts a Rust daemon beside it, connects to it, and shows the dashboard. For installation, see Install Natamux.

What the app does at start

Section titled “What the app does at start”
  1. Starts the sibling natamux-daemon on port 4317, or another free port when 4317 is taken. It listens on 127.0.0.1 only.
  2. Sends the PATH of your login shell to the daemon through a private pipe. If the login shell fails or takes too long, it uses the app’s PATH.
  3. Waits for the daemon’s health check, then opens the window. The dashboard is also available at http://127.0.0.1:<port>/; enter the token from daemon-token when the browser asks.
  4. Ships the Rust natamux and nmx commands beside the app and daemon. A command in a task terminal connects to this daemon.

If the daemon stops unexpectedly, the app shows an error and offers to restart the app.

Menu

Section titled “Menu”
Item What it does
Settings… (Cmd/Ctrl+,) Opens Settings, including the automatic update switch
Check for Updates… Looks for a new version now. On the app menu on macOS, the Help menu on Windows and Linux
Check for Updates Automatically Off by default. Tick it to check every 6 hours. Next to the item above

The app also has View, Task and Tools menus. Links to release pages open in your browser.

Notifications and the Dock

Section titled “Notifications and the Dock”

The Dock icon shows how many tasks need you. Turn on Notify me and allow notifications to see the count. If it still does not show, turn on Badge application icon in System Settings → Notifications → Natamux. With Notify me on, a task that needs you or is done while the app is in the back shows a macOS notification with a sound. See Notifications in the desktop app.

Full Disk Access on macOS

Section titled “Full Disk Access on macOS”

Programs in a Natamux terminal, agents too, get the permissions you give Natamux, as programs in Terminal do.

  1. Open System Settings → Privacy & Security → Full Disk Access.
  2. Click + and add Natamux.app from Applications. Turn it on.
  3. Quit Natamux and open it again.

The grant stays after updates. The first update to a version signed with the Natamux certificate needs it once more: select the old Natamux entry, remove it with −, then add Natamux again.

You can also add Natamux under Developer Tools, so programs built in Natamux skip the Gatekeeper scan. Other permissions, such as the microphone, the camera, AppleScript or the local network, macOS asks for the first time a program needs them.

Custom agents

Section titled “Custom agents”

Settings → Agents lists the built-in agents and your custom agents. A custom agent runs a built-in agent with your own command, such as a shell function that points Claude Code at another model, or runs any other agent CLI. Click Add agent, fill in Id, Based on and Command, then click Save. The new agent shows in every agent picker at once. See Custom agents.

Task ids in the sidebar

Section titled “Task ids in the sidebar”

A sidebar row shows the task’s title, so long titles have room. To see each task’s id before its title, turn on Settings → Appearance → Task ids in the sidebar. With it off, the id is still in the row’s tooltip, the title bar and the details panel, and the sidebar filter still finds a task by its id.

Updates

Section titled “Updates”

The app updates itself, the way other desktop apps do. It looks for a new version when you choose Check for Updates…. Timed checks are off by default; tick Check for Updates Automatically to turn them on.

  1. You choose Check for Updates…, or, with timed checks on, about 30 seconds after the app starts and then every 6 hours, the app asks GitHub for the latest release.
  2. The app checks the signed release and downloads the right file for an install it can update itself. The status bar shows what it does: Checking for updates… (for a check you asked for), then Downloading 1.0.6 · 42 MB. Check for Updates… is off while a check or download runs.
  3. It checks the signature of SHA256SUMS.txt of the release, then the download against SHA256SUMS.txt. On macOS it also checks the new app’s signature and version. A release without a valid signature is not installed.
  4. The status bar shows Restart to update, and the menu has Restart to Update to 1.0.6, while the downloaded update is ready. After Check for Updates…, a dialog also offers Restart Now or Later. A timed check never opens a dialog: it shows one message with Restart Now and What’s New (the release page). A ready update is not checked or downloaded again; Check for Updates… shows its dialog again.
  5. Restart Now, or a click on Restart to update, asks first if an editor has unsaved drafts. Then the app installs the new version and opens again. Tasks, worktrees and settings stay.

Settings → General → Updates shows the running version and, under it, what the updater did last: “Up to date · last checked 3m ago”, “1.0.6 is ready to install”, or the error of the last check. Its Check now… button turns into Restart to Update while an update is ready.

How the new version goes in depends on how you installed the app:

Installed as Update
macOS app in Applications, or any folder you can write Swapped in after you choose Restart Now. If the swap fails, the old app is restored
AppImage Restart Now replaces the file and starts the new one
.deb Restart Now installs it with pkexec dpkg -i, which asks for your password. If that fails, the app shows the sudo apt install command to run
Windows installer The app offers the release page. Run the new Natamux-win-x64.exe; it replaces the old version and keeps your data
.tar.gz, or a macOS app run from the disk image The app tells you about the new version and opens the release page. Download it yourself

Releases from 0.1.18 have files for every system again, so an Intel Mac or Linux install of an older version, such as 0.1.2, updates itself again.

When a check fails, the app tries again at the next check. After Check for Updates… the app shows the error with Try Again, and the status bar shows Update failed until the next check; a click checks again. A failed timed check shows nothing. Every step is written to logs/update.log.

The check sends no data about you or your tasks. See Security and privacy.

Where things are

Section titled “Where things are”

The app keeps its files in the user data folder.

System Folder
macOS ~/Library/Application Support/Natamux
Windows %APPDATA%\Natamux
Linux ~/.config/Natamux
Path in that folder Holds
settings.json Whether timed update checks are on. An older version also kept its repository here
daemon-token The daemon token, readable only by you. It stays the same between runs
daemon-port The running daemon’s loopback port, for the Rust CLI
data/ Tasks, the task index and worktrees (data/tasks, data/worktrees)
logs/daemon.log The daemon’s output
logs/update.log Update checks, downloads and installs
updates/ The downloaded update, until it is installed
app folder The natamux and nmx commands ship beside natamux-daemon

To use the commands in your own shell, see Use the natamux command in your own shell.

Logs

Section titled “Logs”

Open logs/daemon.log to read the daemon’s output. If it stops, the app shows an error with a restart action.

Quit and close

Section titled “Quit and close”
  • Quit stops the daemon, and with it every agent and terminal. The app asks before dropping unsaved editor drafts. Tasks, worktrees and their changes stay.
  • Closing the window quits the app on macOS, Windows and Linux.

Environment variables you may need

Section titled “Environment variables you may need”
Variable Use
--smoke Starts the app and daemon, checks the window and quits. For CI, not daily use
NATAMUX_<AGENT>_COMMAND The program that starts an agent, for example NATAMUX_CLAUDE_COMMAND. Set it in the environment the app starts from. See Environment variables

Limits

Section titled “Limits”
  • The apps are not signed with an Apple or Windows certificate, and not notarized. The macOS app is signed with a Natamux certificate, which keeps your privacy grants after an update. See Install Natamux.
  • The update check reads only the latest release. Pre-release versions are never offered.
