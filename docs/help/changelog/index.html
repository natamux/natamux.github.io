Changelog

All releases are on GitHub releases.

v1.0.13 (2026-10-31)

Section titled “v1.0.13 (2026-10-31)”
  • Add a custom agent in Settings → Agents: a built-in agent with your own command, or any other agent CLI. It shows in every agent picker. See Custom agents.
  • The desktop app sidebar shows each task as a card with its state, agents, stage, branch and diff, and the question of a task that waits for you. Click to open or fold a card; right click opens the menu.
  • The Progress view shows the stages as a node flow, with an If box per branch. The “…” menu on stage nodes is gone; its actions stay on the node. See Progress.
  • The terminal right-click menu no longer shows New Terminal, New Center Terminal and Close Terminal Tab, which did nothing.

v1.0.12 (2026-10-31)

Section titled “v1.0.12 (2026-10-31)”
  • Install or update the desktop app with one command: curl -fsSL https://natamux.github.io/install.sh | sh on macOS, Debian and Ubuntu, or irm https://natamux.github.io/install.ps1 | iex on Windows. The script checks the checksum, and the signature when minisign is installed. See Install with one command.
  • The homepage download button goes to the install command instead of downloading a file.
  • The macOS app is signed with a Natamux certificate, so Full Disk Access stays after an update. The first update to v1.0.12 needs the grant once more. See Full Disk Access on macOS.
  • Programs in a Natamux terminal get a macOS prompt for privacy permissions instead of being denied.

v1.0.11 (2026-10-30)

Section titled “v1.0.11 (2026-10-30)”
  • In the desktop app, the sidebar hides the task id by default, so the title gets the whole row. Settings > Appearance > Task ids in the sidebar shows it again. See Task ids in the sidebar.
  • In the desktop app, the docked details panel has its own width again, from 280 to 560 px, 320 by default. Dragging its edge resizes only the panel. See In the desktop app.

v1.0.10 (2026-10-30)

Section titled “v1.0.10 (2026-10-30)”
  • Name the branch of a task: the Branch field in Start a task, the project pattern git.branchName with {id} and {slug}, --branch in the CLI and branch in the API. See Branch name.
  • Natamux follows the branch the task really uses. When an agent switches the worktree to another branch, the pull request lookup, the CI check, push and the branch delete use it.
  • In the desktop app, each row of the sidebar shows the task id before the title.
  • In the desktop app, the sidebar and the docked details share one width, so dragging either edge resizes both. See In the desktop app.
  • Fix: in the desktop app, the line between the terminals and the docked details panel was 2 px wide. Now it is 1 px.

v1.0.9 (2026-10-30)

Section titled “v1.0.9 (2026-10-30)”
  • In the desktop app, text boxes take the keys of a text field in a web page, such as moving by word, and Page Up and Page Down in boxes of many lines. Long lines wrap, also in Notes of Start a task. See Text boxes.
  • In the desktop app, the rows of History fit the side panel, and Show in main shows the graph over the terminals at full width with author, hash and age. See History tab.
  • Fix: in the desktop app, the side-by-side diff could not scroll to the end of a file when one side had many changed lines at the end. Now it does.
  • Fix: in the desktop app details panel, the Create issue button stretched over the whole row. Now it is compact.

v1.0.8 (2026-10-29)

Section titled “v1.0.8 (2026-10-29)”
  • Fix: in the v1.0.7 desktop app, Start in Start a task closed the app at once when the project’s commands needed no approval. Now the task starts.

v1.0.7 (2026-10-29)

Section titled “v1.0.7 (2026-10-29)”
  • A project’s commands (a stage check or command, a path when.command, stage args and the setup script) run only after you approve them, and again after each change. The desktop app asks after you add a project and in Start a task, and the project settings show Review commands until you approve; without the app, use natamux repo trust. Projects added before were approved at the first start. See Approve the project’s commands.
  • Each task’s terminals get their own NATAMUX_TOKEN, which works only for that task. Agent commands such as natamux done work as before; a gate command such as stage approve typed in a task terminal is refused. The daemon also checks the Host and Origin of requests, and terminal links open only http, https and mailto. See Security and privacy.
  • In the desktop app, each file you open gets its own tab above the editor. Tabs wrap, a dot marks an edit that is not saved, and Mod+W closes the shown file. See Files of the worktree.
  • In the desktop app, the Projects dialog has Browse… buttons next to Folder and Worktree folder. See Add a project.
  • On macOS, the Dock icon shows how many tasks need you once Notify me is on and notifications are allowed. See Notifications and the Dock.
  • The desktop app starts, switches tasks and opens diffs faster. The Done and Cancelled columns show their 50 newest cards with Show 50 more, and a terminal that fell far behind comes back with its last 1,000 lines of history.
  • Token usage counts the turn that runs natamux done or sends a stage back for that stage, and no longer loses the last model call of a turn or the usage of a terminal that ends.

v1.0.6 (2026-10-28)

Section titled “v1.0.6 (2026-10-28)”
  • The desktop app shows what the updater does in the status bar (Downloading 1.0.6 · 42 MB, Restart to update, Update failed) and in a new Version row under Settings → General → Updates. A timed check never opens a dialog: a ready update shows one message with Restart Now and What’s New, and a failed timed check shows nothing. See Updates.
  • In the desktop app, Remove finished workspaces and Delete all done tasks / Delete all cancelled tasks no longer skip a workspace with files that are not committed. The confirm names it and reads Remove anyway or Delete anyway: those files are lost. See Sidebar.
  • In the desktop app, with no task the main area shows Welcome to Natamux with three steps: choose a project, sign in to your agents, set up your workflow. See Add a project.
  • In the desktop app, the Agent and Kind selects and the number fields on the Stages tab of a project’s settings sit on the row of their label, so the page is shorter.

v1.0.5 (2026-10-28)

Section titled “v1.0.5 (2026-10-28)”
  • In the desktop app, a task whose worktree has files that are not committed can now be cleaned up. Remove workspace and Delete task list those files first and offer Remove anyway or Delete anyway, which discard them. The finished banner no longer disables Remove workspace for them. The web dashboard, the CLI and Remove finished workspaces still refuse. For scripts, add force=true to DELETE /tasks/:id or DELETE /tasks/:id/workspace. See When a task is finished.
  • Fix: in the v1.0.4 desktop app for Apple silicon on macOS 26, the green traffic light touched the first letter of the title bar. Now there is a gap.
  • Fix: in the desktop app sidebar, the hover of the “N finished” row stopped before its Remove finished workspaces button. Now it covers the whole row.

v1.0.4 (2026-10-27)

Section titled “v1.0.4 (2026-10-27)”
  • In the Changes tab, comment on a line of a task’s diff, or on a whole file, in the desktop app and the web dashboard. Comments are saved as drafts and stay on their code when the agent edits the file. Send N comments (Mod+Alt+Enter) sends every open comment to the agent in one prompt. Click Resolve when a comment is fixed. See Comment for the agent.
  • An agent that ended its turn and waited 30 minutes, with no window that shows its terminal, pauses: Natamux ends its terminal and keeps its conversation. Show it again and the agent starts again on the same conversation. Change the minutes, or turn it off with 0, with Pause idle agents after (min) on the Stages tab of a project’s settings, or agents.pauseIdleAfterMinutes in .natamux.json. See An idle agent pauses.
  • In the desktop app, the status bar shows the agent nearest its plan limit, such as Claude 84% · 5h, and its menu lists each agent’s windows. A toast says when a window passes 80%, and Start a task shows the share next to each agent. Only Claude Code and Codex tell their limits. See Plan limits.
  • The desktop app has nine more theme families: Ayu, Catppuccin, Dracula, GitHub, Gruvbox, Nord, Rosé Pine, Solarized and Tokyo Night. Pick them under Light theme and Dark theme in Settings → Appearance. See Settings.
  • Deleting a task now also deletes its branch, also when the branch has commits that are not merged. A task whose worktree has changes that are not committed is still not deleted. For a task that used Check on CI, its natamux-ci/ branch on GitHub goes too; before, only a done or cancelled task lost it. Only the branch of the pull request stays on GitHub, with the pull request.
  • Fix: since v1.0.0 the desktop app showed no macOS notifications, played no sound and showed no count on the Dock icon. Now they work again, and a click on a notification opens the task. See Notifications and the Dock.
  • Fix: in a narrow desktop app window, a click on a task in the sidebar drawer only closed the drawer. Now it opens the task.

v1.0.3 (2026-10-26)

Section titled “v1.0.3 (2026-10-26)”
  • An agent may now send a task back from one stage any number of times; before, it stopped after 2. To set a limit, type a number in Agent send backs on the Stages tab of a project’s settings, or set agents.maxSendBacks in .natamux.json. Past the limit the task waits for you, as before. The limit counts CI failures too. See Limit the send backs.
  • In the desktop app, a project with Blur names on shows its names, titles and labels as soft blurred bars, as the web dashboard blurs them, and not as dots. Tooltips still show dots.
  • Fix: with a send-back limit, after a person sent a task back or approved it, the next agent send back from that stage could be refused at once. Now the limit counts only the agent send backs since the last action of a person on that stage.

v1.0.2 (2026-10-26)

Section titled “v1.0.2 (2026-10-26)”
  • In Start a task in the desktop app, Branch from has a folded Remote branches group with the branches of origin that have no local branch, also ones you never fetched. Pick origin/<branch> to start the task from it: Natamux fetches only that branch and makes no local branch for it. See Base branch.
  • In the desktop app, the header of a project’s Settings page reads “Projects / ”. Stages, Issues and JSON are tabs under the header that stay on screen while the page scrolls, and the path of .natamux.json is in the bottom bar.
  • Fix: in the Progress view, a long line under Show evidence ran past the right edge of the stage card. Now it wraps inside the card.
  • Fix: when a stage that ends its terminal ran again in the same terminal within 20 minutes, the terminal could show “The terminal ended.” while the new agent was working. Now it shows the new terminal.
  • Fix: with git-lfs installed by Homebrew, making a task’s worktree could fail with git-lfs: command not found. Natamux’s own git and gh commands now use the PATH of your login shell.

v1.0.1 (2026-10-26)

Section titled “v1.0.1 (2026-10-26)”
  • In the desktop app, an open task has no tabs. Its terminals fill the main area. Progress, Changes, History, Docs, Files and Details are icons on a rail at the right edge of the window, and the rail stays when the details panel is closed. Click the picked view again to close the panel. See In the desktop app.
  • In the desktop app, Changes lists the files and the commit box in the panel and shows the picked file’s diff over the terminals. Docs lists the stage files in the panel and shows the picked one over the terminals. A file from Files opens over the terminals too. Terminals, or Esc, shows the terminals again, and Mod+W closes the open file.
  • In the desktop app, to add a terminal, click the split button in a terminal’s header. On a finished task, Back to wrap-up in a terminal’s header goes back to the wrap-up.
  • In Start a task in the desktop app, the selects (Context from, Skill, Project, Branch from and Agent) sit on the row of their label and are as wide as their text. A long name is cut short.
  • In the desktop app, Enter starts a new line in Notes, in the notes of the edit form, in the send-back reason, in the commit message and in the Ask agent comment.
  • Fix: in the sidebar, the buttons of a project’s header followed its task count, and the rows under a task were not indented. Now the buttons sit on the right and the rows are indented again.
  • Fix: after a task was finished, Reopen agent could show the ended Terminal 1. Now it shows the new terminal of the agent.

v1.0.0 (2026-10-26)

Section titled “v1.0.0 (2026-10-26)”
  • Natamux is now a native app: the desktop app, the daemon and the natamux and nmx commands are Rust programs. The app draws its own window; the daemon still serves the dashboard to your browser. See Desktop app.
  • The app uses the same data folder as the version before, so it opens with your tasks, worktrees, settings and daemon token.
  • The daemon starts on port 4317, or on another free port when 4317 is taken. The natamux command in a task terminal finds it.
  • The app checks the signature of a release with the same release key as before, and installs nothing that fails the check. See Updates.
  • The Docs tab uses the app’s text sizes for markdown and for its file list.
  • The Docker image natamux-daemon runs the Rust daemon. See Self-host with Docker.
  • On Debian and Ubuntu the package is still natamux, so apt install replaces the old version. The app is /opt/Natamux/natamux-app; the natamux-desktop command is gone. If the AppImage does not start, start it with --appimage-extract-and-run. See The AppImage does not start.
  • Each task shows how many tokens its agents used and an estimated cost in USD: a Usage section in the task’s Details tab, a line such as $0.42 est. · 610K tokens under each stage card, and a Cost column in the task table. The cost is an estimate at API list prices. Cursor does not report usage. See Usage.
  • Output in one terminal draws only that terminal. The sidebar, the task list, the details panel and the other panes draw again only when their own data changes.
  • A window without focus stops the age clock of the sidebar and the 60-second checks of the open task. When the window has focus again, it reads once what it skipped. Changes the daemon sends are still read in the background.
  • The open task reads its git state, its events, its stage files and its settings at most once a second. Many changes in a row make one read, and the screen draws again only when the result differs.
  • The sidebar lays out only the rows on screen. The time labels of the sidebar, the task list and the details panel draw again only when one of them changes.
  • In the daemon, a shell that prints a lot no longer holds up the other shells.
  • Fix: a click on the sidebar or details toggle in the status bar could do nothing. Now every click shows or hides the panel.
  • Fix: while Claude Code worked in Terminal 1, the sidebar row and the pane header showed a plain zsh terminal until the agent’s turn ended. Now they show the agent while it prints.
  • Fix: when the agent of a stage with End the agent and close its terminal ended the stage itself (natamux done or natamux stage back), its terminal closed before the agent saw the answer. Now the terminal closes when the agent ends its turn, at most 60 seconds later. See End a stage’s terminal.
  • Fix: in the dashboard, a terminal you ended with exit could leave the screen at once. Now it keeps its last screen and Open a new terminal.

v0.1.43 (2026-10-21)

Section titled “v0.1.43 (2026-10-21)”
  • The stage settings in Project settings → Stages have a Run in a terminal of its own checkbox (ownShell). Checked, the stage runs in Terminal 5 with a new session. Unchecked, it runs in Terminal 1 with the task’s agent. Unchecking also clears the stage’s Agent and Arguments when it can no longer have them. See The Stages tab and Stages in their own terminal.
  • Fix: a stage that started in Terminal 5 kept it after ownShell was turned off. Now an ownShell change moves the stage to the terminal the settings give at its next start. A lane of a group keeps its terminal. See Choose a model.

v0.1.42 (2026-10-21)

Section titled “v0.1.42 (2026-10-21)”
  • A new task answers at once. Natamux makes the worktree and starts the first agent in the background, and the task shows Preparing workspace with the current step. A toast says when the workspace is ready or failed. A failure keeps the task, so Create workspace can try again. See Start a task.
  • The status bar shows background jobs, with a menu of each job, its task and how long it has run. GET /jobs and jobs.changed give the same list. See Background jobs.
  • When Spec or Plan runs in its own terminal, an empty Terminal 1 names the terminal that works now, such as Terminal 5 is working. See Terminals and agents.
  • Fix: a settings change could move a running stage to another terminal, so natamux done, turn ends and send backs reached the wrong stage. Now a stage keeps the terminal it started in until it starts again. See Choose a model.

v0.1.41 (2026-10-20)

Section titled “v0.1.41 (2026-10-20)”
  • In Project settings → Stages, a stage that starts its own agent shows that agent’s icon and its model (or the agent’s name) under its name in the flow chart. See The Stages tab.

v0.1.40 (2026-10-20)

Section titled “v0.1.40 (2026-10-20)”
  • Reopen agent in the wrap-up of a done or cancelled task starts the agent of Terminal 1 again on its last conversation. The task keeps its state. See When a task is finished.
  • The Done and Cancelled columns of the board have a trash button that deletes every task in the column. Natamux asks first and skips a task with changes that are not committed. See Task views.
  • The Overview card of the Progress view is one row of short figures, with the full meaning in a tooltip.
  • On macOS 26, the desktop app’s menu items have icons, so their titles line up with the system items. See Menu.
  • Fix: Copilot CLI printed a warning at start and skipped Claude Code’s hook file in the worktree. Now Copilot shows no warning and reports each event once. See Copilot.

v0.1.39 (2026-10-20)

Section titled “v0.1.39 (2026-10-20)”
  • Rollback… in the Changes tab puts files that are not committed back as they are in the last commit. It is also on a file or folder row, and Mod+Alt+Z rolls back the file in the diff. The toast has Undo. See Roll back changes.
  • The panes of a task are called terminals: Terminal 1, New terminal, and the sidebar tag T1. See Terminals.
  • Fix: when the file list of the Changes tab was narrow, Commit all covered the diff. Now it moves to its own line.

v0.1.38 (2026-10-19)

Section titled “v0.1.38 (2026-10-19)”
  • A subtask is part of its parent’s work: it starts from the parent’s branch, its pull request goes into that branch, and the parent’s next stage waits for its open subtasks, then pulls their work. See Subtasks.
  • Add a subtask with Add subtask… in the row menu, or with natamux task create <title> --parent <id>. See task.
  • A new Settings dialog gathers the app-wide settings. Open it with Settings… in the Account menu or the desktop app menu, or Mod+,. See Settings.
  • The desktop app shows a spinner while it opens, instead of a blank window.

v0.1.37 (2026-10-19)

Section titled “v0.1.37 (2026-10-19)”
  • Click a notification to open its task. The desktop app icon shows how many tasks need you, and File → Keep Computer Awake While Agents Run keeps the computer awake while an agent runs. See Notifications and Menu.
  • In the command palette, Tab cycles the scope through Needs you and each project. See Command palette.
  • After a restart, opening a task brings back every agent of the task, also one that crashed or that you started by hand. An agent you quit stays quit. See A shell after a daemon restart.
  • A terminal hidden for 20 minutes is closed in the dashboard to save memory. Its shell keeps running.
  • Fix: an agent’s git add or git commit could fail on index.lock while the dashboard was open. The dashboard now reads git status without the lock.
  • Fix: typed Vietnamese was garbled when the daemon had no locale. Task shells now get LANG=C.UTF-8. See Task terminals.

Section titled “v0.1.0 (2026-10-10)”

The first release. Run many coding agents in parallel, each task in its own git worktree and terminal, with every task’s state on one dashboard.

What is in it

Section titled “What is in it”
  • Tasks and a dashboard. A table and a board of every task, with a “Needs you” strip. Keyboard first (⌘K or Ctrl+K).
  • A worktree per task. Each task gets its own branch and folder.
  • Five agents. Claude Code, Codex, Gemini CLI, GitHub Copilot CLI and Cursor. Natamux adds hooks for each session.
  • Stages. Context, Spec, Plan, Test spec and Implement side by side, Review, Testing, Release. Change them per project in .natamux.json. Each stage checks its result before it moves on.
  • Changes and history. A file tree, side by side or inline diffs, commit and push, open a pull request, and a branch graph.
  • The natamux command, short name nmx, for you and for agents.
  • Browser or desktop app. No account and no telemetry.
